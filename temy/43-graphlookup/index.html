§1Дерево в коллекции

В отделе кадров у каждой карточки сотрудника есть строка «руководитель». Чтобы узнать всю команду руководителя разработки, кадровик находит карточки, где руководитель — он, затем карточки, где руководители — найденные люди, и так, пока новые карточки не перестанут находиться.

В базе org коллекция employees устроена так же: у каждого из 15 сотрудников поле manager_id хранит _id руководителя, у директора — null. Ссылки внутри одной коллекции образуют дерево: у каждого сотрудника один руководитель, у руководителя может быть несколько подчинённых.

Оргструктура org.employees15 сотрудников · 4 уровня

    • s-002 Павел Демин · разработка
      • s-004 Алексей Ким
        • s-006 Сергей Носов s-007 Дарья Белова s-008 Кирилл Юдин
      • s-005 Марина Власова
        • s-009 Ольга Рябова s-010 Тимур Ахметов
      • s-014 Юлия Ефимова s-015 Максим Седов · инфраструктура

Зелёным — команда Павла Демина, её ищут примеры §2–§4; сам он в свою команду не входит. Отдел указан там, где он меняется: все сотрудники ветки s-002 в разработке, кроме Максима Седова.

Стадия $lookup из главы 6.1 находит только прямых подчинённых: один шаг по ссылке. Подчинённых подчинённых она не видит — для этого нужен ещё один $lookup, а глубина дерева заранее неизвестна.

§2Стадия $graphLookup

Стадия $graphLookup выполняет поиск по ссылке многократно: найденные документы становятся отправной точкой следующего поиска, пока новые документы находятся. Параметры:

startWith — значение, с которого начинается поиск, обычно поле документа потока. connectToField — поле документов from, которое сравнивается с текущим значением: кто подчиняется этому _id. connectFromField — поле найденного документа, которое даёт значение для следующего шага: _id найденного подчинённого. as — массив для всех найденных документов. Пример находит всю команду Павла Демина. Порядок документов в массиве сервер не задаёт, поэтому имена упорядочены выражением $sortArray из главы 4.7.

В команде 9 человек: четверо прямых подчинённых и пятеро подчинённых тимлидов. Сам Павел Демин в массив не попал — поиск начинается с его _id, а документы, где он в manager_id, — уже подчинённые.

Шаги поиска от s-0024 + 5 = 9
ШагИщем manager_id изНайдено
1s-002 (startWith)Ким, Власова, Ефимова, Седов
2s-004, s-005, s-014, s-015Носов, Белова, Юдин (у Кима); Рябова, Ахметов (у Власовой)
3s-006, s-007, s-008, s-009, s-010никого — обход закончен

На каждом шаге значения connectFromField найденных документов становятся значениями для следующего поиска по connectToField. Обход заканчивается, когда шаг ничего не нашёл.

§3Уровень: depthField

Параметр depthField добавляет каждому найденному документу поле с номером шага, на котором он найден. Нумерация с нуля: 0 — прямые подчинённые, 1 — их подчинённые. Пример выводит команду Павла Демина с уровнями, упорядоченную по уровню и имени.

На уровне 0 — четверо прямых подчинённых, на уровне 1 — пятеро разработчиков в командах тимлидов. Поле level есть только в документах массива team, в самих сотрудниках коллекции его нет. Сервер записывает уровень целым числом типа long.

§4Сколько уровней: maxDepth

Параметр maxDepth ограничивает номер последнего шага. С maxDepth 0 выполняется только первый шаг — прямые подчинённые, как у обычного $lookup. Пример сравнивает 0 и 1.

С maxDepth 0 найдены четверо прямых подчинённых. С maxDepth 1 — все 9: в ветке Павла Демина всего два уровня, и второй шаг дошёл до её конца. maxDepth считается так же, как depthField: от нуля.

§5Вверх по дереву

Цепочку руководителей от сотрудника до директора находят обходом в обратную сторону. Начало — manager_id сотрудника. На каждом шаге ищется документ, у которого _id равен текущему значению (connectToField: "_id"), а следующее значение берётся из его manager_id (connectFromField: "manager_id"). Пример строит цепочку для младшего аналитика Романа Ильина.

Цепочка из трёх человек: непосредственный руководитель Егор Мельник (шаг 0), руководитель аналитики Наталья Гурьева (шаг 1), директор Ирина Соколова (шаг 2). У директора manager_id равно null, документа с _id null нет, и обход закончился.

Направление обхода задают два поляодна коллекция
НаправлениеstartWithconnectToFieldconnectFromField
вниз: подчинённые$_idmanager_id_id
вверх: руководители$manager_id_idmanager_id

connectToField — где искать текущее значение, connectFromField — откуда взять следующее. Для обратного направления поля меняются местами.

§6Обход по условию

Параметр restrictSearchWithMatch — фильтр, которому должен соответствовать каждый найденный документ. Документ, который не прошёл фильтр, не попадает в результат и не продолжает обход: его подчинённых сервер не ищет. Пример находит команду директора целиком и только по отделу разработки.

Без ограничения у директора 14 подчинённых — все, кроме неё самой. С ограничением — 9. Выпала Наталья Гурьева из аналитики, а вместе с ней и вся её ветка: Егор Мельник, Вера Панина и Роман Ильин тоже не найдены, хотя фильтр к ним не применялся. Выпал и Максим Седов из инфраструктуры, хотя он подчиняется руководителю разработки.

Если нужно обойти дерево целиком, а убрать из результата только часть документов, после $graphLookup применяют $filter из главы 5.2 к массиву результата.

§7Команды всех руководителей

Без $match перед стадией обход выполняется для каждого сотрудника. С выражениями модуля 5 по массиву результата считаются итоги: $size — размер команды, $sum по пути "$team.salary" — фонд оплаты. Пример оставляет только тех, у кого есть подчинённые.

Руководителей шесть. У директора 14 человек и фонд 3 315 000, у Павла Демина — 9 и 2 090 000. Дальше Алексей Ким и Наталья Гурьева — по 3 человека, Марина Власова — 2, Егор Мельник — 1. Фонд считается по всем уровням команды, без самого руководителя.

§8Дерево категорий

В коллекции categories у каждой категории поле parent_id указывает на родительскую. Обход вверх даёт путь категории к корню — то, что сайт показывает строкой «Техника → Компьютеры → Периферия». Обход вниз даёт все категории внутри раздела. Пример делает оба обхода.

Путь от «Аудио»: «Периферия» (шаг 0), «Компьютеры» (1), «Техника» (2). Внутри «Компьютеров» пять категорий на двух уровнях: «Ноутбуки», «Комплектующие» и «Периферия» прямо внутри, «Аудио» и «Клавиатуры и мыши» — внутри «Периферии».

§9Перепутанное направление

Пример ищет команду Павла Демина, но поля обхода записаны как для движения вверх, а startWith оставлен от движения вниз.

Вместо девяти подчинённых в массиве двое: сам Павел Демин и его руководитель Ирина Соколова. Первый шаг искал документ с _id, равным _id Павла, и нашёл его самого. Дальше обход пошёл по manager_id вверх. Ошибки нет, поэтому направление проверяют по результату: в списке подчинённых не может быть самого руководителя.

§12Проверьте себя

Чем $graphLookup отличается от $lookup?

$lookup делает один шаг по ссылке. $graphLookup повторяет шаги от найденных документов, пока находятся новые.

Какое значение maxDepth оставит только прямых подчинённых?

0: шаги нумеруются с нуля.

Как получить цепочку руководителей вместо подчинённых?

Начать с $manager_id и поменять поля местами: connectToField: "_id", connectFromField: "manager_id".

Почему с restrictSearchWithMatch по отделу разработки пропал Роман Ильин, хотя условие к нему не применялось?

Его руководитель Егор Мельник и руководитель того — Наталья Гурьева — не прошли условие. Документ, не прошедший условие, не продолжает обход, и до Романа поиск не дошёл.

Почему результат $graphLookup упорядочивают $sortArray?

Порядок документов в массиве as сервер не задаёт.

$graphLookup начинает с startWith, ищет документы, у которых connectToField равно текущему значению, и продолжает поиск от их connectFromField, пока находятся новые документы. Все найденные документы попадают в массив as без заданного порядка.

Направление обхода задают поля связи: вниз по дереву — от _id к manager_id, вверх — наоборот. depthField записывает номер шага, maxDepth ограничивает шаги; оба считаются с нуля. restrictSearchWithMatch отсекает документы вместе со всем, что под ними.

Перепутанные поля связи не дают ошибки, а меняют направление обхода; результат проверяют по смыслу.
