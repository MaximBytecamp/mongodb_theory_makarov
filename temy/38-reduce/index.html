$reduce: массив
в одно значение

$reduce проходит по массиву элемент за элементом и на каждом шаге обновляет одно накопленное значение: число, строку, документ или массив. В главе разобраны переменные $$value и $$this, сумма штук, строка из названий, категории без повторов, самый дорогой элемент и роль начального значения. Отдельно показано, когда вместо $reduce достаточно готового выражения.

§1Выражение $reduce

Кладовщик считает, сколько штук товара в накладной. Он начинает с нуля, смотрит первую строку и прибавляет её количество, затем вторую — и так до конца. На каждом шаге у него в голове одно число — сумма уже просмотренных строк.

Выражение $reduce делает с массивом то же: проходит по элементам по порядку и на каждом шаге вычисляет новое накопленное значение из прежнего и текущего элемента. Результат — значение после последнего шага. Запись:

initialValue — значение до первого шага, как ноль у кладовщика. В выражении in доступны две переменные: $$value — накопленное значение после предыдущих шагов, $$this — текущий элемент. Параметра as у $reduce нет, имена переменных фиксированы. Пример считает штуки в заказе 2026-0002 и сравнивает результат с $sum из главы 5.3.

units и units_sum равны 5: один ноутбук, одна веб-камера, трое наушников.

Шаги $reduce по items заказа 2026-0002initialValue 0 → 5
Шаг$$value до шага$$this.qtyin: $$value + qty
начало——0 (initialValue)
1 · Ноутбук ASUS011

Результат шага становится $$value следующего шага. После последнего элемента накопленное значение и есть результат выражения.

Для суммы есть готовое выражение $sum, и оно короче. $reduce нужен там, где готового выражения нет. Следующие разделы показывают такие случаи.

§2Строка из элементов

Названия позиций нужно записать в одну строку через запятую — например, для темы письма покупателю. Готового выражения, которое соединяет массив строк, нет. Накопленное значение здесь — строка, начальное значение — пустая строка. На каждом шаге к строке через запятую дописывается следующее название; на первом шаге запятая не нужна, поэтому $cond проверяет, пустая ли строка.

Четыре названия заказа 2026-0004 записаны через запятую в порядке массива. Запятой нет ни в начале, ни в конце строки: на первом шаге $$value было пустым, и $cond вернул само название.

Накопленная строка по шагамinitialValue ""
Шаг$$value пустое?$$value после шага
1да — без запятойВеб-камера Logitech C920
2нетВеб-камера Logitech C920, Смартфон Xiaomi Redmi Note 13
3нет… Redmi Note 13, Наушники Sony WH-1000XM5

Разделитель ставится перед каждым названием, кроме первого. Без проверки строка начиналась бы с «, ».

§3Массив без повторов

В заказе 2026-0004 две позиции периферии, и в массиве "$items.category" категория «периферия» встречается дважды. Чтобы перечислить категории заказа без повторов, накапливают массив: начальное значение — пустой массив, на каждом шаге категория добавляется, только если её там ещё нет.

Для этого нужны два выражения. $in в форме выражения — {"$in": [значение, массив]} — истинно, если значение есть в массиве; это не оператор фильтра из главы 2.3, а выражение, которое возвращает истину или ложь. $concatArrays склеивает массивы: {"$concatArrays": ["$$value", ["$$this"]]} — накопленный массив и массив из одного текущего элемента.

В categories четыре значения, в unique — три: периферия, смартфоны, аксессуары. Вторая «периферия» пропущена: на третьем шаге $in нашёл её в накопленном массиве, и $cond вернул массив без изменений. Порядок — порядок первого появления категории в заказе.

Аккумулятор $addToSet из главы 4.7 тоже убирает повторы, но работает в $group по документам и не сохраняет порядок. $reduce работает внутри документа и сохраняет порядок массива.

§4Элемент с наибольшим полем

$max из главы 5.3 возвращает наибольшее число, но не элемент, которому оно принадлежит. Чтобы получить самую дорогую позицию целиком, накапливают документ: на каждом шаге сравнивают цену текущей позиции с ценой накопленной и оставляют более дорогую. Начальное значение — документ с ценой 0, его превзойдёт любая позиция.

Самая дорогая позиция заказа 2026-0004 — наушники Sony за 34 990, документ со всеми полями позиции. Начальный документ {"price": 0} в результат не попал: уже на первом шаге его заменила веб-камера.

§5Накопленное значение как ключ группы

Результат $reduce — обычное значение, с ним работают другие выражения. Пример считает длину массива категорий без повторов и группирует по ней все заказы: сколько заказов из одной категории, из двух и так далее.

Заказов с одной категорией 45, с двумя — 40, с тремя — 27, с четырьмя — 8. Всего 120. Заказов из одной позиции 39 (глава 5.1), а из одной категории — 45: ещё шесть заказов состоят из нескольких позиций одной категории.

§6Один знак $ у $$value

Как $$this в главе 5.2, накопленное значение пишется с двумя знаками доллара. Пример сравнивает запись с одним знаком и правильную запись.

wrong равно null. "$value" — путь к полю value заказа, а такого поля нет. $add с отсутствующим значением возвращает null, и этот null переходит из шага в шаг до конца. Ошибки сервер не возвращает. right равно 5.

§7Записи, которые сервер не принимает

Начальное значение обязательно и определяет тип накопленного значения на первом шаге. Пример собирает три записи, которые сервер отклоняет.

Без initialValue — ошибка 40078 при разборе запроса. Пустая строка как начальное значение и $add в in — ошибка 14 на первом шаге: $add складывает только числа и даты. Строка в input — ошибка 40080. Без поля input выражение возвращает null, как $filter и $map.

§8$reduce в Compass

На кадре — конвейер из §3 на вкладке Aggregations коллекции shop.orders: стадия $match по заказу o-0004 и стадия $project с полями categories и unique.

В образце результата $project поле categories — Array (4), поле unique — Array (3): $reduce пропустил одну повторную категорию. Сами значения видны, если раскрыть массив треугольником слева: в unique «периферия» одна и стоит первой, как в заказе.

§10Проверьте себя

Чему равно $$value на первом шаге $reduce?

Значению initialValue.

Почему для суммы штук лучше {"$sum": "$items.qty"}, чем $reduce?

Результат одинаковый, а готовое выражение короче и сразу понятно. $reduce берут, когда готового выражения нет.

Какое начальное значение нужно, чтобы собрать из элементов строку?

Пустая строка "": на первом шаге $concat получает строку. С числом 0 $concat вернёт ошибку.

Чем категории без повторов через $reduce отличаются от результата $addToSet?

$reduce работает внутри одного документа и сохраняет порядок первого появления. $addToSet собирает значения из документов группы, порядок не задан.

Почему {"$add": ["$value", "$$this.qty"]} даёт null, а не ошибку?

"$value" — отсутствующее поле документа. $add с отсутствующим значением возвращает null, и он сохраняется до конца.

Итог главы

$reduce проходит по массиву input по порядку. На каждом шаге выражение in получает накопленное значение $$value и текущий элемент $$this и возвращает новое накопленное значение. До первого шага $$value равно initialValue; результат — значение после последнего шага.

Накопленное значение может быть числом, строкой, массивом или документом; его тип задаёт начальное значение. Так собирают строку из элементов, массив без повторов с $in и $concatArrays, элемент с наибольшим полем.

Для суммы, наибольшего и среднего есть готовые выражения из главы 5.3 — они короче. "$value" с одним знаком даёт null без ошибки; без initialValue — ошибка 40078, строка во input — 40080.
