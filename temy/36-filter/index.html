$filter: отбор
элементов массива

$filter оставляет в массиве только элементы, которые подходят под условие, и возвращает новый массив. Документ при этом остаётся в потоке, меняется только значение поля. В главе разобраны переменная элемента $$this и параметр as, несколько условий, ограничение limit, подсчёт отобранного и $filter внутри $match. Отдельно показано, что получается при пропущенном знаке $ и у документа без массива.

§1Выражение $filter

Кладовщик получил накладную и выписывает из неё только позиции периферии: веб-камеры, наушники, клавиатуры. Накладная остаётся целой, рядом появляется выписка — короткий список нужных строк.

В главе 5.1 из массива брали элементы по номеру. Когда нужные элементы определяются не номером, а содержимым, используют выражение $filter. Оно проверяет условие на каждом элементе массива и возвращает новый массив из тех элементов, для которых условие истинно. Порядок элементов сохраняется. Запись:

input — массив, который проверяется. as — имя, под которым текущий элемент доступен в условии. cond — условие, записанное выражением, как в $cond из главы 4.2: {"$eq": [значение, значение]}, {"$gte": [...]}. Внутри условия элемент записывается с двумя знаками доллара: "$$item", его поле — "$$item.category". Два знака отличают переменную выражения от поля документа, которое пишется с одним знаком.

Пример отбирает у заказа 2026-0002 позиции категории «периферия».

В periphery — две позиции из трёх: веб-камера Logitech и наушники Sony. Ноутбук ASUS не прошёл условие. Каждая позиция осталась документом со всеми пятью полями: $filter не меняет элементы, он только решает, оставить элемент или нет.

$filter по items заказа 2026-00023 элемента → 2
$$item$$item.categorycond: равно «периферия»В результате
0 · Ноутбук ASUS VivoBook 15ноутбукиfalse—
1 · Веб-камера Logitech C920периферияtrue0
2 · Наушники Sony WH-1000XM5периферияtrue1

Условие вычисляется для каждого элемента по очереди, и $$item каждый раз — следующий элемент. В последнем столбце — номер элемента в новом массиве: номера считаются заново.

В главе 4.6 те же позиции отбирали парой стадий $unwind и $match: заказ превращался в три документа, и два из них проходили отбор. $filter оставляет один документ заказа, а выписку кладёт в его поле.

§2Переменная $$this и длина отобранного

Параметр as необязателен. Без него текущий элемент называется this и записывается "$$this". В остальных примерах книги используется эта короткая запись.

Результат $filter — массив, поэтому его длину можно получить выражением $size из главы 5.1. Пример для заказа 2026-0004 выводит число всех позиций, позиции периферии и их число.

В заказе четыре позиции, из них периферия — две: веб-камера (3 штуки) и наушники (1 штука). periphery_lines равно 2 — длине массива periphery. Выражение $filter в примере записано дважды: один раз для самого массива, второй — внутри $size. Сервер вычисляет его оба раза.

§3Несколько условий

Условие cond — любое выражение, которое даёт истину или ложь. Несколько условий соединяют выражением $and: {"$and": [условие, условие]} истинно, когда истинны все условия списка. Это выражение, а не оператор фильтра из главы 2.4, поэтому условия внутри записываются в форме выражений: {"$gte": ["$$this.qty", 2]}.

Пример отбирает у заказа 2026-0004 дешёвые позиции, купленные несколькими штуками: количество от 2, цена ниже 10 000.

Прошли две позиции: веб-камера (3 штуки по 6 790) и пауэрбанк (3 штуки по 4 290). Смартфон Xiaomi куплен в двух штуках, но стоит 18 990 и не проходит второе условие. Наушники стоят 34 990 и куплены в одной штуке — не проходят оба.

$and истинно, только если истинны оба условия строки. Одного условия, как у смартфона, недостаточно.

§4Первые подходящие: limit

Параметр limit ограничивает число элементов в результате: $filter проверяет элементы по порядку и останавливается, когда набрал limit подходящих. Пример берёт у заказа 2026-0004 только первую позицию периферии.

В результате одна веб-камера: она стоит в массиве раньше наушников. Наушники тоже подходят под условие, но до них $filter не дошёл. limit не выбирает «лучшие» элементы — только первые по порядку массива.

§5Число отобранных как ключ группы

Длина результата $filter — число, и по нему можно группировать, как по $size в главе 5.1. Пример раскладывает все заказы по числу позиций периферии.

В 63 заказах периферии нет, в 48 — одна позиция, в 9 — две. Вместе 120. Заказы без периферии остались в результате с ключом 0: $filter вернул им пустой массив, а длина пустого массива — 0.

Зелёным — заказы с периферией: 48 + 9 = 57. С $unwind заказы без периферии исчезли бы из потока после $match, и строки с нулём не было бы.

§6$filter внутри $match

Стадия $match принимает выражения через $expr — так в главе 2.8 сравнивали поля между собой. Условие «у заказа есть хотя бы одна позиция периферии» записывается как «длина результата $filter больше нуля». Пример сравнивает такой отбор с фильтрами по массиву из главы 2.6: путём items.category и оператором $elemMatch.

Попарно счётчики совпадают: 57 заказов с периферией и 24 заказа, где периферия куплена от двух штук. Для отбора документов фильтр из главы 2.6 короче и может использовать индекс по items.category; условие с $filter внутри $expr сервер вычисляет для каждого документа и индекс для него не применяет. Поэтому для отбора документов берут фильтр. $filter нужен, когда отобранные элементы нужны дальше: их выводят, считают или передают другому выражению.

§7Склады с остатком

У товара в массиве stock бывают склады с остатком 0: товар туда завозили, но он закончился. Пример отбирает склады с ненулевым остатком в поле in_stock и оставляет только товары, у которых таких складов меньше, чем всех.

Таких товаров 8. У шести из них остался хотя бы один склад: у ноутбука Acer Nitro пустой склад Москва-2, но на складе Екатеринбург 40 штук. У смартфона Samsung Galaxy A55 и монитора Dell по одному складу, и он пустой, поэтому in_stock у них — пустой массив. Второе условие сравнивает длины двух массивов одного документа: это то сравнение полей, ради которого нужен $expr.

§8Один знак $ вместо двух

Переменная элемента пишется с двумя знаками доллара. С одним знаком "$this.category" — это путь к полю документа: сервер ищет у заказа поле this с вложенным полем category. Пример сравнивает обе записи на заказе 2026-0002.

wrong — пустой массив, хотя периферия в заказе есть. Поля this у заказа нет, его значение не равно «периферия» ни для одного элемента, и условие всегда ложно. Сервер не сообщает об ошибке: запись допустима, просто означает другое. Правильная запись в right находит две позиции.

Такую ошибку видно только по результату. Если $filter неожиданно вернул пустой массив у всех документов, первым делом проверяют число знаков доллара в условии.

§9Документ без массива

Поля gifts (подарки к заказу) у заказов нет. Пример применяет к нему $filter напрямую и через $ifNull с пустым массивом, как в главе 5.1.

gifts равно null: без входного массива $filter возвращает null, а не пустой массив. gifts_or — пустой массив: $ifNull подставил [] вместо отсутствующего поля, и $filter отработал на нём. Разница важна, если дальше стоит $size: от null он даёт ошибку 17124, от пустого массива — 0.

§10Параметры, которые сервер не принимает

Пример собирает три записи $filter, которые сервер отклоняет, и печатает код и текст каждой ошибки.

Строка вместо массива в input — ошибка 28651. Без cond — ошибка 28650. Третья ошибка, 17276, возникает, когда задан as, а в условии стоит $$this: после as элемент называется только заданным именем, и переменной this нет. Вторая и третья ошибки обнаруживаются при разборе запроса, до чтения документов; первая — на первом документе, где promo оказался строкой.

§13Проверьте себя

Чем результат $filter отличается от результата пары $unwind и $match?

$filter оставляет один документ и кладёт отобранные элементы в массив. $unwind и $match дают по документу на каждый подходящий элемент, а документы без подходящих элементов исчезают.

Почему условие {"$eq": ["$this.category", "периферия"]} не находит ни одной позиции?

С одним знаком доллара это путь к полю this документа, которого нет. Переменная элемента пишется "$$this.category".

Какие элементы вернёт $filter с "limit": 1, если под условие подходят три элемента?

Первый из трёх по порядку массива.

Что вернёт $filter, если у документа нет поля из input?

null. Чтобы получить пустой массив, input оборачивают в {"$ifNull": ["$поле", []]}.

Когда для отбора заказов лучше фильтр {"items.category": "периферия"}, чем $expr с $filter?

Когда нужно только отобрать документы: фильтр короче и может использовать индекс. $filter нужен, если отобранные элементы используются дальше.

Итог главы

$filter проверяет условие cond на каждом элементе массива input и возвращает новый массив из подходящих элементов в прежнем порядке. Элементы не меняются, документ остаётся в потоке один. Текущий элемент в условии — $$this или имя из as, всегда с двумя знаками доллара; с одним знаком получается путь к полю документа и пустой результат без ошибки.

Несколько условий соединяют выражением $and, limit оставляет первые подходящие элементы. Длина результата через $size служит счётчиком, ключом группы и условием в $match через $expr; для простого отбора документов короче фильтр по массиву.

Без входного массива $filter возвращает null, со строкой — ошибку 28651. Поле, которого может не быть, заменяют пустым массивом через $ifNull.
