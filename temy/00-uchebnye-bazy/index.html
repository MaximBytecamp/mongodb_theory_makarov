§1Какие базы нужны

На сервере должно оказаться пять баз и двенадцать коллекций. Четыре базы — эталонные: на них построены все примеры, и менять их нельзя. Пятая, sandbox, — песочница: в ней делают упражнения, вставляют, обновляют и удаляют.

§2Файлы с данными

Данные лежат в папке stend/seed репозитория практик: по одному JSON-файлу на коллекцию. Там же скрипт generate.py, который эти файлы собирает. Запускать его не нужно: файлы уже готовы, и у всех они одинаковые.

Имя каждого файла говорит, куда его загружать:

shop.orders.json

shopИмя базы — до первой точки.
ordersИмя коллекции — между точками.
jsonФормат: массив документов в JSON.

shop.orders.json→база shop→коллекция orders→120 документов

Внутри файла — массив документов в квадратных скобках. Так начинается shop.products.json:

Обратите внимание на поле added. В обычном JSON нет типа «дата», поэтому она записана особым объектом { "$date": "…" } — это формат Extended JSON. И mongoimport, и Compass понимают его и сохраняют поле как настоящую дату, а не как вложенный документ. Если открыть файл и «поправить» такую запись руками, в базе окажется уже не дата, и запросы по времени из следующих глав перестанут работать.

способ 1 Docker

  • §5 и глава 1.1а.
способ 2 Скрипт
  • сервер установлен, есть mongoimport;
  • одна команда на все двенадцать коллекций;
  • §6.
способ 3 Compass вручную
  • есть только сервер и Compass;
  • двенадцать раз одно и то же действие мышью;

Результат у всех трёх одинаковый. Скрипт и Docker удобнее ещё и тем, что их можно повторить в любой момент — когда данные в песочнице разъедутся после упражнений.

§5Способ 1. Docker

Если стенд запускается в Docker, отдельно загружать ничего не нужно. При первом docker compose up -d сервис seed видит пустой сервер и сам заливает все файлы из stend/seed:

Вернуть базы в исходное состояние — docker compose run --rm reset. Как поставить Docker и что делать при ошибках, разобрано в главе 1.1а.

§6Способ 2. Скрипт с mongoimport

mongoimport — консольная утилита MongoDB: читает JSON-файл и записывает документы в указанную коллекцию. Она входит в набор MongoDB Command Line Database Tools и ставится отдельно от сервера:

Скачайте ZIP-архив MongoDB Command Line Database Tools для Windows со страницы mongodb.com/try/download/database-tools и распакуйте. Права администратора для архива не нужны. Добавьте папку bin из архива в переменную PATH или запускайте mongoimport по полному пути к этой папке. Проверка: mongoimport --version.

Через Homebrew: brew tap mongodb/brew и brew install mongodb-database-tools. Проверка: mongoimport --version.

Со страницы mongodb.com/try/download/database-tools скачайте пакет .deb или .rpm для вашего дистрибутива и установите его (sudo apt install ./mongodb-database-tools-….deb). Проверка: mongoimport --version.

Загружать двенадцать файлов по одному не нужно: в папке stend лежат скрипты, которые проходят по всем файлам и берут имена базы и коллекции из имени файла.

Флаг -ExecutionPolicy Bypass разрешает запустить этот скрипт один раз, не меняя настроек Windows: без него PowerShell по умолчанию отказывается выполнять файлы .ps1.

Первая строка появилась потому, что кадр снят на компьютере без mongoimport: load.sh в таком случае сам берёт утилиту из запущенного контейнера со стендом. Если mongoimport установлен, этой строки не будет, а остальной вывод совпадёт.

Внутри скрипта для каждого файла выполняется одна и та же команда. Её полезно знать и саму по себе — например, чтобы перезагрузить одну коллекцию:

--db shopВ какую базу писать. Базы нет — сервер создаст её при первой записи.из имени файла
--collection ordersВ какую коллекцию.из имени файла
--file …Путь к файлу с данными.обязательно
--jsonArrayФайл — это массив [ … ], а не документы по одному на строку. Без флага импорт падает.обязательно
--dropУдалить коллекцию перед загрузкой. Без него повторный запуск упрётся в дубли _id.для повтора

Адрес сервера не указан — mongoimport по умолчанию подключается к mongodb://localhost:27017. Другой задаётся флагом --uri.

§7Способ 3. Вручную через Compass

Если нет ни Docker, ни mongoimport, но сервер и Compass работают, файлы загружаются мышью. На кадрах ниже — пустой сервер, на который загружаем первую коллекцию, shop.products.

  1. Подключитесь к серверуОткройте подключение к mongodb://localhost:27017. Если учебных баз ещё нет, в списке только три служебные: admin, config, local.
  1. Создайте базу и первую коллекциюКнопка Create database справа вверху. В поле Database Name — имя базы из файла, в Collection Name — имя коллекции. Для shop.products.json это shop и products. Compass не создаёт пустую базу без коллекции, поэтому оба поля обязательны. Галочку Time-Series не ставьте.
  1. Откройте импортОткройте новую коллекцию: щёлкните по products под базой shop в левой панели. Коллекция пустая — нажмите Add data → Import JSON or CSV file или кнопку Import data посередине.
  1. Выберите файлОткроется окно выбора файла вашей системы. Найдите в папке репозитория stend/seed/shop.products.json. Проверьте строку To collection: коллекция должна совпадать с именем файла. Stop on errors можно не отмечать.
  1. Нажмите ImportВнизу слева появится сообщение Import completed. 21 documents imported., а в коллекции — 21 документ.

Посмотрите на поле added на кадре: Compass показывает его свёрнутым, и внутри уже дата, а не объект с $date. Это и есть работа Extended JSON из §2.

Остальные одиннадцать файлов загружаются так же. Если база уже есть, создавать её заново не нужно: наведите на неё в левой панели, нажмите + и создайте только коллекцию.

Осторожно: у Compass нет «перезаписать»

Повторный импорт в коллекцию, где документы уже есть, их не заменяет: у каждого документа свой _id, и Compass сообщит Import completed 0/21 with errors: E11000 duplicate key error… — ни один документ не добавится. Чтобы загрузить коллекцию заново, сначала удалите её: ⋯ рядом с коллекцией в левой панели → Drop collection. Скрипт из §6 делает это сам флагом --drop.

§8Проверить, что всё загрузилось

После любого способа нажмите в Compass Refresh в списке баз. Должно быть восемь строк: пять учебных баз и три служебные.

§10Проверьте себя

В какую базу и коллекцию загружается файл hh.interviews.json?

База hh, коллекция interviews: имя базы стоит до первой точки, имя коллекции — между точками. После загрузки в ней 60 документов.

Зачем в файлах даты записаны как { "$date": "…" }, а не строкой?

В JSON нет типа «дата». Запись $date — формат Extended JSON: mongoimport и Compass превращают её в настоящую дату. Строка так и осталась бы строкой, и сравнение по времени работало бы неправильно.

После упражнений в sandbox.products 19 документов вместо 21. Что делать?

Перезагрузить коллекцию: docker compose run --rm reset в Docker, скрипт из §6 или одна команда mongoimport … --drop. В Compass — удалить коллекцию и импортировать файл заново. Чинить документы руками не нужно.

Вы дважды импортировали shop.orders.json через Compass. Сколько документов окажется в коллекции?

120. Вторая попытка не добавит ни одного: у каждого документа тот же _id, и сервер отклонит дубликаты. Compass покажет Import completed 0/120 with errors, но данные не удвоятся.

Итог главы

Учебные данные — двенадцать JSON-файлов в stend/seed репозитория практик; имя файла задаёт базу и коллекцию. Загрузить их можно Docker-стендом, скриптом с mongoimport или вручную через Compass — результат одинаковый, и проверяется он числом документов в каждой коллекции. Когда числа сошлись, переходим к главе 1.1: что такое сервер, база и коллекция и как до них дойти из кода.
