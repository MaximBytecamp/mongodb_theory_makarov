## 1. Чем модуль 3 отличается от модуля 2

Примеры модуля 2 — фильтры, и `tools/snippets.py` собирает их из одного литерала.
В модуле 3 примеры процедурные: создать коллекцию с правилом, перехватить отказ
сервера, построить индекс, прочитать план. У каждого драйвера свой тип ошибки и
свой способ отправить команду, поэтому код записывается **на каждом языке целиком**
в `tools/chapters3.py` (ключ `"plain"`), а подсветку собирает `codeedit.highlight`.
Маркеры в главе те же: `<!--EX 3.N имя-->`, `<!--ERRORS 3.N-->`, `<!--CHEAT 3.N-->`,
`python3 tools/snippets.py expand 3.N`.

Набор коллекций модуля — `SCOPE["3"]` в `tools/examples.py`: `products`, `orders`,
`events` (база `logs`), `sandbox` (база) и `box` (`sandbox.products`).
Объявления, общие для всех примеров главы, — в `EXTRAS[("3.N", язык)]`
(в главе 3.1 — коллекция `catalog` и правило `schema`).

Кадры — `tools/shots-m3.mjs`. Состояние песочницы перед каждым кадром готовит
mongosh (`STATE` в скрипте) — то же, что оставляет пример раздела. Область кадра
и плотность заданы `Emulation.setDeviceMetricsOverride` (1600×969), поэтому
кадр не зависит от размера окна Compass, а Compass может работать в фоне.

## 3. Главы

### 3.1 Правила на уровне базы: `$jsonSchema` — **готова** (06.10.2026)
`temy/19-jsonschema`. `sandbox.catalog`, `sandbox.checked`, `sandbox.products`.
Семь примеров: сервер принимает любой документ → правило как фильтр (`$nor`) →
коллекция с `validator`, код 121 → разбор `errInfo` → ключевые слова (`enum`,
`pattern`, `minLength`, `items`, лишнее поле) → `collMod` и `validationLevel`
(`strict` / `moderate`) → `validationAction: "warn"`, `listCollections`, `getLog`.
Кадры 108–116. Проверено на сервере: `properties` проверяет поле, только если
оно есть; `type: "integer"` не поддерживается (код 9); `additionalProperties: false`
без `_id` отклоняет всё; `int64` из Go и `double` правило `int` отклоняет;
mongosh пишет целые числа как `int`.

### 3.2 Индексы: одиночные, составные, уникальные — **готова** (06.10.2026)
`temy/20-indeksy`. Индексы строятся на копиях `sandbox.events` (`journal`) и
`sandbox.customers` (`clients`): первый пример сам пересоздаёт копию, поэтому
повторный прогон начинается без индексов, а `logs` и `shop` их не получают.
Работа индекса показана цепочкой стадий плана — функция `plan` в заготовке
(`EXTRAS` для Python/Ruby, `TOP_EXTRAS` для Go/C++); время не показывается.
Семь примеров: копия и `_id_` → `service_1` (COLLSCAN → FETCH → IXSCAN) →
составной `service_1_status_1`, префикс, порядок без SORT → удаление лишнего,
SORT по `ts` → уникальный `email_1`, 11000 и `keyValue` → уникальный по `city`
не строится → `null` и частичный индекс. Кадры 117–123 (вкладка Indexes,
Explain Plan, окно Create Index). Проверено: `_id_` не удаляется (72), повтор
индекса возвращает имя, тот же ключ с `unique` — 86, с другим именем — 85,
обратная сортировка идёт по индексу `backward`, `items.sku` — multikey.

### 3.3 Как читать `explain` — **готова** (09.10.2026)
`temy/21-explain`. Копия `sandbox.events`, функция `summary` в заготовке — стадии
плана и три счётчика одной строкой (команда `explain` с `verbosity: executionStats`).
Шесть примеров: разделы отчёта и счётчики без индекса (42/0/1200) → выбранный и
отклонённый планы → `hint` по трём индексам и `$natural` → покрывающий запрос
(`PROJECTION_COVERED`, документов 0) → `SORT` и индекс `service_1_ts_-1` (`LIMIT`,
10/10/10) → ESR: 42/42 с SORT, 18/18, 18/5. Сравнения — только через `hint`: при
равной работе сервер выбирает между индексами непредсказуемо. Время не печатается:
в Compass один и тот же запрос показывал 1, 7, 8 и 15 мс. Кадры 124–130 (Explain Plan,
Raw Output). Практикум «Онлайн-разбор запроса» — ссылка из §6, ESR там подробнее.

### 3.4 Текстовый поиск: текстовый индекс, `$text`, `$search`
`shop.products.title`. Один текстовый индекс на коллекцию; `default_language:
"russian"` и стемминг («ноутбук» находит «ноутбука»); фраза в кавычках, исключение
`-слово`, `$meta: "textScore"`. Подводка из 2.7: `$regex` без якоря индекс
не использует. Индекс — на копии в `sandbox`.

### 3.5 География: `2dsphere`, `$near`, `$geoWithin`, `$geoIntersects`
Координат в базах нет. Пример создаёт в `sandbox` коллекцию пунктов выдачи
(города доставки из `shop.orders.delivery.city`) с GeoJSON-точками; порядок
`[долгота, широта]` — главная ошибка главы. `$near` требует индекс `2dsphere`.

### 3.6 Скрипт целиком
По образцу 1.9 и 2.9 (`WHOLE`): скрипт из `mongodb-practice/scripts`, который
ставит правило и индексы на копию журнала и печатает отчёт с планами запросов.

## 4. Практика и контрольная точка

**ПР-03 «Журнал сервиса: индексы и правила»** — правило на события журнала
(обязательные `ts`, `service`, `level`, `status`), индексы под три запроса
дежурного, план каждого запроса до и после. `check.py` смотрит на правило
и индексы коллекции.

**КТ-03 «Замедлившийся отчёт»** — отчёт с COLLSCAN: найти по `explain`, какой
индекс нужен, построить, показать планы до и после.
