# Как пишется глава справочника

Документ собран по готовому модулю 1: всё, что здесь описано, взято из
`temy/01-klient-baza-kollekciya` … `temy/08-udalenie`. Модуль 2 и дальше пишутся
так же — тогда книга останется одним изданием, а не набором похожих страниц.

Карта тем и порядок изучения — в [PLAN.md](PLAN.md). Проверка текста перед
публикацией — в [shared/TEXT_REVIEW.md](shared/TEXT_REVIEW.md).

---

## 1. Порядок работы над главой

1. Взять тему из PLAN.md и проверить, что все операторы в ней уже разобраны
   в предыдущих главах. Оператор не может появиться в примере раньше своей главы.
   Единственное исключение — когда без него пример не собрать; тогда он вводится
   одной строкой с отсылкой на будущую главу (так сделано с `$in` в ПР-01).
2. Завести папку `temy/NN-slug/index.html`, скопировать скелет из соседней главы.
3. Написать текст и примеры на **Python**, добиться, чтобы всё работало на стенде.
4. Добавить главу в `tools/examples.py` (словарь `CHAPTERS`).
5. Написать те же примеры на C++, Go и Ruby.
6. Прогнать: `run` → `apply` → `report`. Пока `report` не даёт «ОТЛИЧ: 0»,
   глава не готова.
7. Снять кадры Compass на живом стенде.
8. Собрать архивы примеров: `python3 tools/archives.py build`.
9. Прогнать текст по `shared/TEXT_REVIEW.md`.
10. Прописать главу в `index.html` (оглавление) и в пагинаторы соседних глав.

## 2. Устройство страницы

Порядок блоков одинаков во всех главах. Слева — класс, справа — что внутри.

```
div.running        колонтитул: «Справочник по MongoDB · модуль N», номер главы
header.chapter-head
  span.chapter-num номер: 1.5
  h1               заголовок в две строки через <br>
  p.lead           3–4 предложения: что разберём и чем это кончится
  blockquote.quote одна строка — см. §8 «Открытые вопросы»
dl.passport        4 поля: Категория, Уровень, Связанные темы, Зачем это знать
div.runbox         как запускать примеры этой главы (см. §4)
nav.contents       «В этой главе» — нумерованный список ссылок на #s1…#sN
h2#s1 … h2#sN      разделы главы
h3                 «Итог главы» — один абзац
div.pager          ссылки на соседние главы
div.colophon       подпись автора
```

### Обязательные последние разделы

В каждой содержательной главе модуля 1 четыре раздела идут в конце и всегда
в этом порядке:

| Раздел | Что внутри |
|---|---|
| `<что-то> в Compass` | `figure.shot` с кадром того же запроса на тех же данных |
| `Частые ошибки` | `div.table-scroll.errors-table` — три столбца: что написано, что происходит, как правильно |
| `Проверьте себя` | 4–5 блоков `<details>`: в `<summary>` вопрос, внутри ответ |
| `Шпаргалка` | `div.cheat` — короткие карточки «название → строка кода» |

Служебные главы (`00-uchebnye-bazy`, `00a-…`, `01a-…`) строятся по шагам
(`§N Шаг M. …`) и «Проверьте себя» могут не иметь.

## 3. Четыре языка

Читатель выбирает драйвер кнопкой в колонтитуле; выбор хранится в
`localStorage` под ключом `mongodb-book-lang` и действует на всю книгу.
Механика — в `book.js`, переключение видимости — в `styles.css`.

Правила:

- блок, который существует в каждом языке, дублируется четыре раза
  с `data-lang="python|cpp|go|ruby"`;
- это касается не только кода: `errors-table`, `cheat` и отдельные абзацы
  тоже бывают языковыми (`<p data-lang="ruby">…`), когда поведение драйвера
  различается — например, курсор в Ruby перезапрашивает данные;
- блок без `data-lang` виден всем: так оформляются команды оболочки `mongosh`,
  вывод сервера и всё, что от драйвера не зависит;
- `data-os="win|mac|linux"` работает так же, ключ `mongodb-book-os`;
  система определяется сама, пока читатель не выбрал её кнопкой.

Парные блоки «код и его вывод» — `figure.code` и следом `figure.code.code--out`
с тем же `data-lang`. Вывод вписывается не руками: его подставляет `apply`
(см. ниже).

Код и вывод рядом, когда нужно сравнить два языка, оборачиваются в `div.duo`.

### Подсветка

Разметка внутри `<pre>` ручная, классы из `styles.css`:
`s` — строка, `f` — вызов или имя функции, `k` — ключевое слово, `n` — число,
`c` — комментарий, `o` — оператор, `fld` — имя поля документа.

## 4. Примеры и их прогон

Главный принцип: **вывод в книге — это настоящий вывод программы на стенде.**
Руками выводы не пишутся и не правятся.

### Как глава описывается в `tools/examples.py`

```python
CHAPTERS = {
    "1.5": ("05-proekciya", "Проекция: какие поля вернуть", False),
    #        папка в temy/    заголовок                     пишет ли в базу
}
```

Третий элемент — признак «глава меняет данные». У таких глав перед прогоном
базы сбрасываются, и в `runbox` пишется требование сбросить базы.

### Команды

```bash
python3 tools/examples.py starters             # заготовки в mongodb-practice/lessons
python3 tools/examples.py run python 2.1 2.2   # прогон выбранных глав одного языка
python3 tools/examples.py run all              # все главы, все языки
python3 tools/examples.py apply                # записать настоящие выводы в книгу
python3 tools/examples.py report               # сверить книгу с прогоном
```

`report` должен дать **«ОТЛИЧ: 0»**. Любое расхождение означает, что в книге
стоит выдуманный вывод.

**Прогоны разных языков нельзя запускать одновременно** — они сбрасывают одну
и ту же базу.

### Блоки «для чтения»

Фрагмент, который не должен выполняться (заведомо ошибочный код, кусок без
подключения, псевдокод), помечается `data-run="no"` на `figure.code`. Прогон
его пропускает. В модуле 1 таких блоков 20.

### Архивы примеров

После любой правки кода в главе:

```bash
python3 tools/examples.py run <языки> <главы>
python3 tools/examples.py apply
python3 tools/examples.py report          # ОТЛИЧ: 0
python3 tools/archives.py build           # пересобрать zip с примерами
python3 tools/archives.py verify python 2.1
```

`build` кладёт `temy/<глава>/primery/mongodb-glava-<N.M>-<язык>.zip` и
проставляет строку «Архив» в `runbox`. В архиве — все примеры главы готовыми
программами, `compose.yaml` с одним раннером, данные и `README.md` с ожидаемыми
выводами. Zip детерминированный: одинаковый вход даёт одинаковый файл.

Go-файлы в архиве получают `//go:build ignore` — иначе несколько `main`
в одной папке не собираются.

## 5. Кадры Compass

Кадр снимается на живом стенде: что на кадре — то и в базе. Скриншоты руками
не собираются и не рисуются.

```bash
env -u ELECTRON_RUN_AS_NODE "/Applications/MongoDB Compass.app/Contents/MacOS/MongoDB Compass" \
  --ignore-additional-command-line-flags --remote-debugging-port=9222 &
node tools/shots-m2.mjs                  # все кадры модуля
node tools/shots-m2.mjs 57-hh-dva-usloviya  # один кадр
```

`tools/shots-m1.mjs` написан под кадры модуля 1, `tools/shots-m2.mjs` — под
модуль 2; для нового модуля делается свой файл по их образцу. Общая обвязка —
`tools/lib.mjs`.

Что выяснилось при съёмке модуля 1 и повторять не нужно:

- навигация — по спискам в рабочей области, а не по дереву слева: дерево
  бывает свёрнуто, а одинаковые имена коллекций есть в разных базах;
- кнопку **Reset** не трогать: она открывает панель истории запросов, и та
  лезет в кадр;
- все поля запроса заполнять явно, включая пустые: Compass помнит их
  по коллекции;
- импорт файла автоматизируется через `DOM.setFileInputFiles` с настоящим путём;
- поля панели запроса — `#query-bar-option-input-filter`, `…-sort`, `…-project`
  и так далее; вставлять в них текст надёжнее через буфер обмена
  (`navigator.clipboard.writeText` + `Meta+V`), потому что редактор
  сам дописывает закрывающие скобки при посимвольном вводе;
- Compass после запуска стоит на экране Welcome и ни к чему не подключён;
  кнопка **CONNECT** появляется в боковой панели только после щелчка по самому
  подключению, поэтому порядок такой: щелчок, потом кнопка;
- вкладки рабочей области копятся между прогонами и попадают в верх кадра;
  закрывать их нужно **до** перехода в коллекцию: закрытие текущей вкладки
  уводит рабочую область на соседнюю коллекцию, и запрос уходит не туда
  (поэтому же переход проверяется и по имени коллекции, а не только базы);
- кнопка **Expand all** у документа скрыта, пока на него не наведён курсор;
  после раскрытия список уезжает вниз, и первый документ нужно вернуть
  в поле зрения `scrollIntoView`;
- вид документов (список, JSON, таблица) Compass помнит между запусками —
  выбирать его в скрипте явно;
- перед снимком окно нужно вывести на передний план
  (`osascript -e 'tell application "MongoDB Compass" to activate'`), иначе
  Electron перестаёт перерисовывать и снимок зависает.

Имя файла кадра: `NN-<что>-<где>.png`, сквозная нумерация по книге
(`shots/`, сейчас занято до 60). Языковые варианты одного кадра различаются
суффиксом: `25-vscode-pr01-python.png`.

Каждый кадр подписывается `figcaption`, и **каждое поле на кадре разбирается
в тексте** — кадр без разбора не ставится.

## 6. Данные

Четыре учебные базы плюс песочница; состав — в [README.md](README.md).
Данные детерминированные, грузятся с `--maintainInsertionOrder`: порядок
документов в файле совпадает с порядком вывода `find` без сортировки, и числа
в книге сходятся с тем, что получит студент.

Отсюда два следствия:

- **нельзя менять seed-файлы, не пересняв всё, что на них опирается** —
  выводы примеров, кадры Compass, ответы практик и тестов;
- любая глава, которая пишет в базу, работает с `sandbox`, а не с учебной базой.

## 7. Практики и контрольные точки

Практика идёт после логически завершённого набора тем: 1–2 прикладные задачи,
разобранные до кода. Страница — `praktiki/<slug>/index.html`, решение —
папка в репозитории `mongodb-practice`: `README.md`, данные, решение на четырёх
языках и `check.py`, который смотрит на состояние базы, а не на код.

Контрольная точка — та же предметная область без разбора, с отчётом, который
читает человек, не заглядывающий в базу.

Практикум (как `praktiki/onlayn-razbor-zaprosa`) — короткая работа без
кода на языках, вся механика в оболочке и внешних инструментах.

## 8. Открытые вопросы

**Эпиграф в шапке главы.** В справочнике по MongoDB `blockquote.quote` стоит
на 13 страницах, включая главы модуля 1. В справочнике по Python эпиграфы
удалены 20.09.2026 во всех главах. Решение по MongoDB не принято: либо убрать
везде одним проходом, либо оставить как часть оформления этой книги. До решения
новые главы пишутся с эпиграфом — чтобы страницы не расходились между собой.
